# PaintBox: code review of #77 and rebase for 0.2.5

[#77](https://github.com/CruxCoach/CruxCoach/pull/77) by Hugie, reviewed on its head `568b78679` against `main`, then rebased onto `feat/0.2.5-release`. The rebased branch with the fixes is the draft [#90](https://github.com/CruxCoach/CruxCoach/pull/90). The board simulator test, the UI pass and real-board tests come next.

## What the review checked

| Check | Result |
| --- | --- |
| Bluetooth writes only after a user action | Yes. Pictures go out on "Send now" and, with live painting on, on each stroke. Only the user turns live painting on. Connecting sends nothing. Cancelling a photo sends the previous picture again, but only if the photo preview already reached the board. Automatic climb sends pause while PaintBox is open. |
| Network and permissions | No network code. No new permission, and the manifest is unchanged. No new library. |
| Photo import | Through Android's photo picker (`PickVisualMedia`). Without Google services it falls back to the document picker. The file is copied to the app's cache for decoding and deleted right after. The long edge is limited to 2048 px. |
| What is stored | Only hold colours, as one JSON file per picture in the app's own files. Never the photo, its position or its source. |
| Without Google services | Only platform and AndroidX APIs (`ImageDecoder`, `AtomicFile`, the photo picker) and kotlinx-serialization. |
| Aurora power limits | Pictures use the connected board's own encoder, the same as every climb. API-2 boxes keep their 18 W budget for every picture, all holds white included. When the budget would leave the wall dark, the send is refused. API-3 has no client-side budget, as for climbs. |
| Quantum | Pictures use four PaintBox layers of their own, separate from the climb layers. Before any change, PaintBox checks 92 LEDs per colour, and the Bluetooth layer checks it again. Layers of other climbers stop the send before anything changes. |
| Disconnect, background, board change | Live painting pauses on each of them and never turns itself back on. Leaving the screen also gives automatic climb sends back. |

## Findings and what changed

1. **Shared board picker (fixed).** The last commit of #77 made the picker's board choice wait inside the picker dialog, for every user. Picking an Aurora board while a catalogue download runs would keep the picker busy until the download ended, and closing it would lose the pick. #90 leaves the picker as it is. PaintBox follows the saved board instead, and picking the open board again keeps the picture.
2. **Shiny Wall (fixed).** Shiny Wall is a new board in 0.2.5. PaintBox let you paint on it, but "Send now" then failed with "Board data is missing". PaintBox now says that it doesn't work with Shiny Wall yet.
3. **Quantum picture and climbs (message fixed, limit stays).** A picture stays on the controller as PaintBox's own layers. The climb page then refused to light a climb and asked to refresh the catalogue, which cannot help. It now says to clear the picture in PaintBox. Letting a climb replace the picture, as on the other boards, would change the Quantum layer logic; that is left for later.
4. **German texts (fixed).** The photo background tool showed "BG Color" and "Pick Background Color" in German too. Now "Background" / "Hintergrund".
5. **Guides (fixed).** `docs/en/PAINTBOX.md` and `docs/de/PAINTBOX.md` described implementation details and a first local test run. They are now user guides. The changelog has an entry crediting Hugie.
6. **Smaller points, unchanged for now:**
   - An all-white picture that an API-2 box cannot light within its budget gets the generic send error.
   - On Quantum, live painting replaces all PaintBox layers on every change. The simulator test will show whether the wall flickers.
   - A phone that relays the board for others keeps forwarding their sends while you paint.
   - The photo file is copied to the cache without a size limit before decoding.

## Rebase

- Hugie's two feature commits carry over with their author. Their conflicts are resolved: `sendRawLeds` keeps Hugie's sending state and also clears the lit frame as on the release branch, and `SettingsNavigationTest` keeps both new tests. The whitespace-only commit is dropped.
- The fixes are separate commits on top, so each one can be read, changed or dropped on its own.
- Shared code that every user goes through changes only where PaintBox needs it: the Bluetooth connection (sending state, a pause flag for automatic sends), the Quantum layer rack (separate PaintBox identities and the new message), the board views (paint gestures and colour overlay, active only inside PaintBox), the LED colour palette (a filter) and the Settings overview.

## Tests

Focused unit tests on the rebased branch: PaintBox (view model, projection, storage, photo sampling, screen), settings navigation, the Quantum rack policy and layer manager, the climb send controller and connection cleaning. CI runs the full suite on #90.
